# 영한 금융 번역 모델 실제 학습 보고서 — finance-v3

최종 기록: 2026-09-09. 공개 Marian 모델의 학습 가능한 가중치를 실제로 갱신했고, 사전에 정한 dev·test 판정 기준을 모두 통과했다. 아래 학습 전후 결과는 동일한 토크나이저와 FP32 추론 조건에서 용어 사후 보정·검수 번역 메모리를 적용하지 않은 비교다. **학습된 FP32 모델과 로컬 추론 CLI를 제공하며 앱은 Argos를 유지한다.** 첫 INT8 변환과 시작 임베딩 보존 v2 변환 모두 별도 dev 비교 기준을 통과하지 못해 앱에 등록하지 않았다. 이 결과로 이번 실험을 종료했고 추가 변형·설정 스윕·재학습은 하지 않았다. 실제 앱 검증 기록은 [구현 상태](../../IMPLEMENTATION_STATUS.md)를 따른다.

## 모델과 데이터

기반 모델은 헬싱키대학교 Language Technology Research Group이 개발한 [Helsinki-NLP/opus-mt-tc-big-en-ko](https://huggingface.co/Helsinki-NLP/opus-mt-tc-big-en-ko)다. 고정 revision은 `ae8606b7b29a495f31ce679cee2007f536a3a5ce`이며, 실제 로딩한 전체 파라미터는 **211,223,552개**, 학습 가능한 파라미터는 **209,126,400개**다. 어댑터만 학습하는 방식이 아니라 학습 가능한 전체 파라미터를 갱신했다.

| 분할 | 금융 | 일반 | 합계 | 사용 범위 |
|---|---:|---:|---:|---|
| train | 160 | 40 | 200 | 가중치 갱신 |
| dev | 30 | 10 | 40 | 50·100·150 step 비교와 체크포인트 선택 |
| test | 40 | 20 | 60 | 선택 완료 후 기반 모델과 최종 비교 |
| 전체 | 230 | 70 | 300 | 도우미가 작성한 영한 문장쌍 |

이 실험은 실제 사용자 검수쌍 **0개**에서 시작했다. train/dev의 provenance는 `assistant-authored training; not user-reviewed`, test는 `assistant-authored evaluation; not user-reviewed`다. 영어와 한국어를 도우미가 독자 작성했으며, 사람이나 금융 번역 전문가의 검수를 받은 자료가 아니다. 한국어 표현은 다모다란 공식 번역이 아니다.

train의 금융 문장은 8개 주제에 20쌍씩 배분했다. 정의뿐 아니라 조건·비교·부정·가상 수치 예시를 포함하며, 기존 47개 용어·제목을 문장 속에서 다룬다. test는 별도 작성 에이전트가 train/dev 문장과 모델 출력을 보지 않고 작성·고정했다. train/dev와 test의 14,400개 조합에서 원문 완전 중복과 숫자 정규화 중복은 0개였다. 다만 작성 도구와 주제의 공통점이 있어 독립적인 실제 문서 표본과 동등하지 않다.

자료 구성·개념 참고 URL·공개 병렬 자료의 접근 조건은 [데이터 설명](README.md), [학습 데이터 명세](metadata.json), [평가 데이터 명세](test-metadata.json)에 있다. 다모다란의 긴 원문을 복사하거나 승인되지 않은 외부 병렬 자료를 수집하여 학습에 넣지 않았다. 운영 DB·메모·업로드·검수 내보내기도 사용하지 않았다.

## 토크나이저 복원과 비교 기준

원본 배포본의 `vocab.json`은 한국어 target SentencePiece의 ID 체계와 맞았지만 영어 source SentencePiece와는 맞지 않았다. 이 상태에서 CPU와 XPU 모두 영어 입력의 미등록 토큰과 비정상 번역이 관찰됐다. 앞선 `finance-v2` 실행은 19회 갱신에서 중단했으며 유효한 학습 성과로 집계하지 않는다. 이 실행에 최종 test를 사용하지 않았다.

원본 `.training/base-model/`은 보존하고, 원래 `source.spm`의 ID에서 영어 `vocab.json`을, `target.spm`의 ID에서 한국어 `target_vocab.json`을 복원한 `.training/prepared-model/`을 만들었다. `separate_vocabs=true`이며 두 SPM 파일과 기반 가중치는 바꾸지 않았다. 원본·복원본 가중치 파일 SHA-256은 같다. 복원 절차와 별도 어휘 검사는 [학습 도구 안내](../../scripts/model-training/README.md)를 따른다.

이 보고서의 **학습 전(raw base)과 학습 후(finetuned)는 모두 복원된 같은 토크나이저를 사용한다.** 따라서 아래 점수 차이에 토크나이저 복원 효과를 학습 성과로 더하지 않는다. 원본 어휘 오류로 망가진 번역과 학습 후 번역을 비교한 수치도 아니다.

Intel Arc 140V의 XPU에서 FP32로 실행했다. 런타임은 PyTorch `2.8.0+xpu`, Transformers `4.57.6`, SentencePiece `0.2.2`, Safetensors `0.7.0`, SacreBLEU `2.5.1`이다.

## 고정 test의 학습 전후 결과

test 60쌍은 모델 선택 후 한 번의 최종 비교에 사용했다. 원문 문장이나 결과로 추가 학습·사전 교정·체크포인트 선택을 다시 하지 않았다. 아래 표는 소수점 여섯 자리로 반올림했다. 판정은 반올림 전 값으로 수행했으며 전체 수치는 [최종 평가 원본](../../.training/runs/finance-v3/evaluation-summary.json)에 보존한다.

| 영역 | 문장 수 | chrF 학습 전 | chrF 학습 후 | 변화 | BLEU 학습 전 | BLEU 학습 후 | 변화 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 금융 | 40 | 29.736046 | 33.790239 | +4.054193 | 2.922553 | 9.605595 | +6.683042 |
| 일반 | 20 | 32.679527 | 35.942196 | +3.262669 | 5.827112 | 9.313832 | +3.486720 |
| 전체 | 60 | 30.668730 | 34.473414 | +3.804684 | 3.910144 | 9.531970 | +5.621826 |

| 영역 | 용어 적중/대상: 전 → 후 | 전체 문장의 숫자 검사 일치: 전 → 후 | 원문에 숫자가 있는 행 보존: 전 → 후 |
|---|---|---|---|
| 금융 | 15/48 → 25/48 | 39/40 → 39/40 | 3/3 → 3/3 |
| 일반 | 해당 없음(0개) | 20/20 → 20/20 | 2/2 → 2/2 |
| 전체 | 15/48 → 25/48 | 59/60 → 59/60 | 5/5 → 5/5 |

전체 용어 적중 비율은 **31.25% → 52.083333%**, 차이는 **+20.833333%p**다. 이는 지정한 한국어 용어의 표기 적중이며 문장 의미 정확도 52%라는 뜻이 아니다. 일반 문장에는 평가 용어가 없어 용어 적중률을 100%로 처리하지 않는다. 빈 결과와 출력 상한 도달은 두 모델 모두 전체 60개에서 각각 0개였다.

숫자 검사는 아라비아 숫자·부호·백분율의 토큰별 개수를 비교한다. **모든 숫자 검사가 완벽히 통과한 결과는 아니다.** `TEST-F03`은 두 모델 모두 원문의 `during the year`를 `1년 동안`으로 옮겨 원문에 없던 숫자 `1`이 생겼고 전체 숫자 검사에서는 불일치로 기록됐다. 원문에 명시적 숫자가 있던 5개 행은 두 모델 모두 보존했다. 평가 데이터 명세의 `numericOrUnitRows: 6`은 단위만 있는 행까지 포함하므로 실행 지표 `numericRowCount: 5`와 정의가 다르다. 숫자를 영어 단어로 쓴 경우나 통화·단위의 의미가 옳은지는 이 검사만으로 확인하지 못한다.

chrF 서명은 `nrefs:1|case:mixed|eff:yes|nc:6|nw:0|space:no|version:2.5.1`, BLEU 서명은 `nrefs:1|case:mixed|eff:yes|tok:none|smooth:exp|version:2.5.1`이다. 하나의 도우미 작성 한국어 참조와 비교했고 BLEU는 별도 한국어 형태소 분석 없이 계산했다. 다른 벤치마크나 토큰화 설정의 점수와 직접 비교할 수 없다.

## 판정과 남은 한계

`devGate.passed=true`, `testGate.passed=true`, `promotionEligible=true`다. 금융·일반 하위 판정도 모두 통과했고 실패 이유 목록은 비어 있다. 사전에 고정한 기준은 금융 용어 적중률 최소 5%p 증가(기반 값 95% 이상인 경우 예외), 전체·금융·일반 chrF/BLEU 1점 초과 하락 금지, 숫자 검사 비율 하락 금지, 빈 결과·상한 도달 금지, 실제 가중치 변화와 동일한 추론 조건 확인이다. 숫자 검사의 기존 불일치가 남아도 비율이 악화되지 않았으므로 이 기준은 통과했다.

이 결과는 작은 합성 표본에서 개선이 관찰됐다는 근거다. 60문장 결과를 다모다란의 긴 HTML/PDF 전체나 모든 금융 문장에 일반화할 수 없다. 학습과 참조 번역에 독립 전문가 검수가 없고, 단일 참조·용어 표기 매칭은 자연스러운 동의어를 놓치거나 용어가 들어간 오역을 적중으로 셀 수 있다. test 의미를 보고 향상된 예시만 고르는 방식의 재학습은 하지 않았다.

최종 점수 산출 후 도우미가 의미를 비교했을 때, 일부 문장은 학습 후에도 틀렸거나 이전보다 나빠졌다. 이는 사람의 독립 검수 결과가 아니며 다음 관측을 학습 데이터나 선택 기준에 다시 반영하지 않았다.

- `TEST-F03`: `cash receipts`를 현금 유입 문맥에서 **현금영수증**으로 옮기는 문제가 학습 전후 모두 남았다.
- `TEST-F08`: 학습 후 무형자산상각을 상환액으로 옮기고, 현금흐름 계산에서 더해 주는 조정을 현금 자체를 늘리는 것처럼 표현했다.
- `TEST-F14`: 지급 시점에 대한 내용을 지급액으로 바꾸는 문제가 학습 후 나타났다.
- `TEST-F30`: 학습 후 주주잉여현금흐름과 차입자본의 관계가 혼동됐다.
- `TEST-G12`: 학습 후 `covered`를 덮는다는 뜻 대신 가리킨다는 표현으로 옮겼다.
- `TEST-G15`: 부정의 의미가 뒤집히는 문제가 학습 전후 모두 남았다.

용어 적중 증가나 전체 평균 점수 상승은 개별 문장 회귀가 없다는 뜻이 아니다. 문서 읽기에서는 원문 대조와 사용자 검수가 계속 필요하다.

이 보고서의 원시 FP32 성능을 CTranslate2 양자화본이나 앱의 문장 분할·용어 보정·검수 메모리 적용 결과와 동일하다고 주장하지 않는다. 변환 후 dev 비교, 모델 무결성, 앱 등록, 실제 번역·저장·캐시 동작은 [구현 상태](../../IMPLEMENTATION_STATUS.md)와 [학습 도구 안내](../../scripts/model-training/README.md)에서 별도로 확인한다.

2026-09-09 09:25:22.929383 UTC에 기록된 **첫 INT8 변환 후 dev 비교는 실패**했다. 금융 BLEU는 FP32 15.777430 → INT8 13.841892, 일반 BLEU는 11.563406 → 10.026970으로 각각 허용 하락 1점을 초과했다. 전체 chrF는 42.637108 → 42.617487, 용어는 14/31 → 14/31, 숫자 검사는 40/40 → 40/40이었다. 이 비교는 선택본의 저장된 dev 예측 40개만 사용했고 최종 test를 다시 읽지 않았다. 첫 판정에 따라 앱 등록을 실행하지 않았고 Argos를 유지했다.

[읽기 전용 원인 진단](../../.training/runs/finance-v3/parity-diagnosis.json)에서는 선택 FP32 모델의 decoder 시작 pad 임베딩이 학습되어 L2 norm `0.01271195337176323`인데 표준 CTranslate2 Marian 변환이 마지막 pad 행을 제거하고 0 임베딩으로 시작하는 차이를 확인했다. HF와 CTranslate2의 beam 종료 규칙도 달랐다. 원본·변환본의 출력 40개 중 24개가 같았지만 각 차이의 영향은 분리해 측정하지 않았다. 따라서 이 실패를 INT8 양자화만의 탓으로 단정하지 않고 **변환된 CPU INT8 런타임 전체의 비교 실패**로 기록한다.
