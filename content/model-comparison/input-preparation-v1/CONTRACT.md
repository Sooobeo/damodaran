# 공통 입력 준비 v1 — S1 입력·평가 계약

정책 ID `input-preparation-v1-s1-20260913`. 이 문서는 [인수인계 28절](../../../TRANSLATION_HANDOFF_20260911.md#28-공통-입력-처리와-의미-관계-검사-개선-실행-계획)의 S1 산출물이다. 원문과 평가 주석을 먼저 확정하며 S2 선택기·S3 검사기·S4 번역 생성은 아직 실행하지 않는다. 자료의 고정 상태와 바이트 해시는 [동결 manifest](freeze-manifest.json), 현재 등록의 실측은 [입력 감사](CURRENT_INPUT_AUDIT.md), 사전 출처는 [별도 기록](DICTIONARY_SOURCES.md)을 따른다.

## 1. 범위와 출처

개발 집합은 **16단위(금융 8·일반 8), 구성별 16출력, C0~C3 총 64출력**으로 확정한다. 이 수를 결과 관측 후 바꾸지 않는다. 단위는 하나의 번역 대상 블록과 같은 문서·버전의 참고 블록 묶음이다. 다른 구성에서도 대상 텍스트와 단위를 바꾸지 않는다. 모든 주석은 도우미 작성이며 `humanReviewed=false`다.

| 층 | 단위 | 성격 | 구조 근거 |
|---|---|---|---|
| 금융 공개 원문 | IP1-F01~F04 | 저장된 R01의 33·38번, R05의 53·57번 블록. 모두 기존 Marian v4/v5 train의 원문과 완전/부분 중복하는 회귀 자료다. 새 독립 원문으로 세지 않는다. | 실제 source_version_id·block ID·sort_order·structure_json·본문·원본 파일 해시 |
| 금융 합성 | IP1-F05~F08 | 상대 %/%p와 통합 이후/도중의 2개 최소대립쌍 | 도우미가 작성한 HTML 구조 호환 fixture. 실존 문서·실제 추출로 표시하지 않음 |
| 일반 합성 | IP1-G01~G08 | 부정 범위·시점·나눗셈 방향·형평성 정책의 4개 최소대립쌍 | 도우미가 작성한 구조 문서. 같은 쌍은 같은 그룹으로 묶음 |

공개 원문은 이 PC에 저장된 바이트를 읽기 전용으로 대조했으며 새 다운로드를 하지 않았다. R01에는 시각상 제목처럼 보여도 `paragraph`로 저장된 블록이 있다. 이를 절 제목이나 부모 목록으로 승격하지 않는다. R05에는 실제 heading level이 있어 같은 버전의 선행 제목 스택을 기록할 수 있다. 대상과 바로 앞뒤 블록은 C0 재현을 위해 모두 보존하고, 선행 제목을 추가로 보존한다. 이 묶음은 원본 DOM 전체나 전체 문서 구조 복원을 뜻하지 않는다.

공개 원문·그 인용이 들어 있는 평가 파일은 Git에서 제외되는 `.training/comparisons/input-preparation-v1/source-bundles/`에만 둔다. 추적하는 manifest에는 ID·출처·해시·개수·상대 경로만 기록한다. 합성 자료 및 일반 사전·정책은 `content/`에 둔다. 개인 메모·북마크·진도·검수쌍·운영 번역은 읽거나 복사하지 않는다. 입력 준비 자료는 가중치 학습용 train이 아니다.

## 2. C0~C3 공통 정체성과 차이

[audit-identity.json](audit-identity.json)의 등록 ID `hymt-contextual-q26-20260910-nativejob`를 C0 기준으로 고정한다. Hy-MT2 7B GGUF Q8 가중치·실제 runtime 파일·GGUF tokenizer overrides·Jinja 템플릿·공통 번역 지시·CPU 4 threads·생성 설정 전체가 비교 불변량이다. seed 42, temperature 0.7, top_k 20, top_p 0.6, repeat_penalty 1.05, 출력 상한 4096, context 8192를 포함하며 나머지 필드도 감사 JSON의 execution 전체와 같아야 한다. 하드웨어/메모리·소유 프로세스 제어는 새 실행 증거에 별도로 남긴다.

| 구성 | 문맥 | 사전 |
|---|---|---|
| C0 | 현 앱 `existing-title-neighbors-v1`를 정확히 재현 | 실제 등록 catalog 54개와 현재 matcher |
| C1 | 아래 구조 문맥 v1 | C0와 동일 |
| C2 | C0와 동일 | 새 의미 사전 v1과 출현별 선택 정책 |
| C3 | C1과 동일 | C2와 동일 |

C0는 `title_en + '\n' + title_ko + '\n' + neighbors.map(text).join('\n')`를 JS UTF-16 `.slice(0,10000)`한 문맥이다. neighbors는 대상과 같은 버전의 `sort_order BETWEEN target-1 AND target+1`을 순서대로 읽으며 **대상 자체도 포함**한다. 합성 문서의 한국어 제목이 없으면 빈 문자열을 사용한다. 별도의 명제나 정답을 한국어 제목으로 채우지 않는다. 기존 앱과 같은 UTF-16 자르기 결과·대상 중복은 C0/C2의 기준 동작으로 기록한다. 이를 C1/C3에도 남기는 것은 개선 계약이 아니다.

현 bridge는 일반 앱 glossary를 받아도 등록 catalog를 사용한다. S2의 별도 비교 입력기는 등록 코드 사본을 변경하지 않고 C0와 동일한 프롬프트를 먼저 재현해야 한다. 새 사전은 C2/C3에 명시적으로 전달해 최종 prompt에서 반영됨을 확인한다. 파이프라인은 `동결 source 묶음 → 소속 검증 → C0 또는 새 문맥 → C0 또는 새 사전 선택 → 같은 번역 템플릿/Jinja → 같은 native tokenize → 비교 전용 producer`다. 평가 폴더/manifest의 주석·질문·정답을 이 경로의 파라미터로 넘기지 않는다.

실제 토크나이저로 렌더링된 **전체 prompt**를 `add_special=false, parse_special=true`로 센다. 현재 runtime의 엄격한 조건 `promptTokens + 4096 < 8192`를 유지하므로 입력 최대는 4095토큰이다. S1에서는 GGUF metadata·템플릿만 감사했고 실제 native tokenizer 호출은 0회다. 실제 토큰 수·C0 동일성·C0~C3 prompt 해시 고정은 S2 완료 조건이다. S1 문서만으로 S4를 시작하지 않는다.

## 3. 새 문맥 선택 정책

1. resource → sourceVersion → targetBlock 소속을 검증한다. 버전·블록·문서 중복 ID, 없는 참조, 같은 버전 내 순서 충돌, 텍스트/구조 해시 불일치면 입력 전체를 거부한다. 다른 버전의 유사 문단으로 대체하지 않는다.
2. 대상의 Unicode 문자열을 입력 파일의 UTF-8 바이트 해시로 보존한다. 줄바꿈·수식·부정·한정사를 정규화하거나 원문을 잘라 맞추지 않는다. C1/C3 배경에서는 같은 블록 및 정확히 같은 대상 텍스트를 제거한다.
3. 후보 순위는 실제 선행 heading 스택(상위→하위), 명시 저장된 부모/목록 도입 관계, 바로 앞 문단, 바로 뒤 문단 순이다. 동일 우선순위에서는 sort_order를 사용한다. 관계를 판단할 추가 모델은 사용하지 않는다. 부모/절/목록 깊이 정보가 없으면 `unsupported_structure`로 남기며 위치만 보고 부모라고 단정하지 않는다.
4. 이번 실제 저장 표에는 row/cell/rowSpan/colSpan/header 데이터가 있으나 의미상 행·열 제목 연결은 불완전하다. 원문에서 명시된 `header=true`와 해석 가능한 단일 격자에서만 좌표 근거를 기록하는 후속 S2 fixture를 허용한다. `header=false` 첫 행을 자동 헤더로 승격하거나 표 제목·단위를 추측하지 않는다. 이번 16개 번역 대상은 표가 아니다. 표 의미 검사·PDF 부모 구조 복원은 지원했다고 표시하지 않는다.
5. 문맥 조각은 `{sourceVersionId,blockId,order,kind,text,textSha256,structureSha256,reason,evidence}`를 가진다. 부분 조각이면 UTF-16 시작/끝과 substring도 기록한다. 원문 인용은 선택 근거이며 주석 정답이 아니다.
6. 대상·기본 지시·전체 사전 힌트·출력 여유를 먼저 확보한다. C1/C3 후보를 위 순서대로 하나씩 전체 블록 경계에서 추가하고 매번 완성 prompt를 실제 토큰화한다. 이번 v1은 블록 안 문장 분할을 하지 않는다. 넘는 블록은 제외하고 다음 후보를 시험한다. 블록마다 `selected`, `target_duplicate`, `unsupported_structure`, `budget_excluded`, `outside_section` 등을 기록한다.
7. 다음 절 heading은 참고 본문으로 넣지 않는다. 이웃 본문이 실제 heading 경계를 넘는 경우 제외한다. C0/C2는 기존 이웃 선택을 그대로 보존한다. 대상과 지시·필수 힌트만으로 예산을 넘으면 그 단위는 `input_over_budget`로 거부하며 모든 구성의 비교를 보류한다.

문맥과 사전 선택 사이의 순환을 막는다. C2/C3 뜻 선택에 사용할 증거 후보는 위 구조 규칙으로 만든 source-only 후보 묶음이다. C2에서는 **실제로 C0 문맥 문자열에 남은 인용만**, C3에서는 토큰 예산으로 최종 선택한 문맥의 인용만 유효하다. 구현 순서는 대상만으로 선택한 사전 → 문맥 후보 선택 → 실제 남은 인용으로 사전 선택을 한 번 재계산 → 예산을 넘으면 낮은 우선순위 문맥과 그에만 의존한 힌트를 함께 제거한다. 제거만 허용하고 다시 넣는 반복 최적화는 하지 않는다. 대상 자체의 뜻 근거는 항상 사용할 수 있다. 이 결정은 C1과 C3의 문맥이 사전 토큰 때문에 달라질 수 있음을 뜻하므로 실제 차이를 출력별로 보고한다.

## 4. 의미 사전 정책

[sense-dictionary.json](sense-dictionary.json)의 일반적인 뜻·허용 한국어 표현·적용/제외 조건·출처만 사용한다. 한국어 표기는 원문 사전의 공식 번역이라고 하지 않는다. 긴 복합구를 우선하고 같은 출현 범위의 단독어 힌트를 중복 적용하지 않는다. 서로 다른 출현에는 각각 다른 뜻을 선택할 수 있다.

힌트는 기존의 `출현 원문 → 선택 한국어 (뜻: definition_ko)` 형식이다. source·한 개의 target·해당 sense의 definition_ko만 prompt에 넣고 실제 출현/문맥 인용·출처 URL·적용/제외 판정·다른 허용 표현은 sidecar에 둔다. target은 조건이 성립하는 allowed_renderings 중 사전 순서의 첫 항목이며 명시 근거가 없으면 생략한다. 동일 source/sense/target은 한 번 렌더링하고 다른 sense는 별도 항목으로 보존한다. 확신할 근거가 없거나 둘 이상의 뜻이 남으면 `ambiguous_no_hint`로 기록하고 힌트를 생략한다. 평가 ID·쌍 ID·domain 정답 라벨·한국어 명제/정답·모델의 과거 오역·평가 용어 목록을 selector가 읽지 못하게 allowlist로 입력을 구성한다. domain별로 사전을 강제하지 않는다.

현재 공통 지시는 금융 의미일 때만 용어 참조를 사용하도록 되어 있다. 이를 네 구성에서 바꾸지 않으므로 비금융·일반 수량/문법 뜻은 `suppress_nonfinancial_hint`로 기록해 잘못된 금융 힌트를 억제하는 데 사용하고 prompt에는 렌더링하지 않는다. 금융·회계 뜻의 `hint_financial`만 위 형식으로 전달한다. 일반 뜻을 직접 가르치는 새 공통 지시는 후속 별도 실험이며 이번 사전 효과에 섞지 않는다.

새 사전은 등록54의 단어 수를 늘린 앱 교체본이 아니라 **별도 8개 초점 개념의 의미 사전**이다. C2/C3는 새 사전만 사용하며 C0의54개를 암묵 병합하지 않는다. 어휘 범위가 줄어드는 효과도 이 실험의 사전 변화에 포함한다. 사전 효과를 분리해서 해석하고, 금융/일반의 모든 선정 용어를 사전 밖 용어까지 평가한다. S4 출력 관측 후 사전을 보충해 같은 실험을 다시 돌리지 않는다.

## 5. 추론 전에 고정하는 평가

전체 **핵심 명제 48개, 질문 32개(핵심 16개), 선정 용어 출현 39개**다. 금융은 24·16(핵심8)·23, 일반은 24·16(핵심8)·16이다. 출현의 위치·뜻·허용 동의 표현은 평가 파일에만 있고 입력 사전에 주입하지 않는다. 용어39는 선정 출현 수이며 원문의 모든 용어 또는 독립 표본39개가 아니다. 단어의 모든 반복 출현을 자동 증식하지 않는다. 각 지표의 0분모는 `not_applicable`/`not_evaluated`이며 100%가 아니다.

평가는 먼저 각 단위 전체를 원문 대조해 critical/major/minor/neutral/보류와 정확한 근거를 기록한다. 3개 핵심 명제를 맞혔어도 다른 문장의 중요 오류를 면제하지 않는다. 용어는 의미와 허용 표현을 함께 만족해야 하며 동의어를 문자열 정답과 동일시하지 않는다. 자연스러움은 1(이해 방해)·2(뜻은 이해되나 어색함)·3(자연스러움)과 근거로 별도 기록한다. 자연스러움 점수는 의미 오류를 상쇄하지 않는다.

질문 답변자는 **단위×후보별 새 context**에서 그 한국어 대상 번역과 질문2개만 받는다. 추가 한국어 학습 문맥은 이번 개발에서 빈 문자열로 고정하며 질문 정답은 대상 번역에서 답할 수 있게 작성한다. 새 답변자는 영어 원문·정답·같은 원문의 다른 후보·인접/동일/최소대립쌍의 다른 출력·이 대화의 자료 작성 이력을 보지 않아야 한다. `fork_turns=none` 등의 격리가 가능한 답변자를 사용하고 노출/모델/배정 차이를 기록한다. 하나의 응답 context에 여러 단위를 묶지 않는다. 질문 2개 답변과 근거를 동결한 뒤 별도 원문 채점자가 채점한다. 후보 출력 순서는 별도 seed `input-preparation-v1-review-20260913`의 해시 정렬로 익명화하며 매핑은 답변자에게 주지 않는다. 독립 답변자 부재는 질문 미완료이며 root 대체 답변을 만들지 않는다.

단위별 C0 대비 **개선/유지/회귀/보류**를 금융 공개·금융 합성·일반 합성으로 나누어 보고한다. 동일 쌍의 두 문장은 같은 문서 그룹이며 독립 표본으로 해석하지 않는다. 새 중요 오류, 핵심 명제의 새 손상, 일반 단위의 의미·질문·용어 회귀가 하나라도 생긴 후보는 확대하지 않는다. 보류가 남으면 선택을 보류한다. 총합만 좋아진 후보를 선택하지 않는다.

S6 후보의 개발 선택 조건은 모든 16개 기술·원문·질문 평가 완료, 위 회귀 거부 통과, 그리고 C0 대비 중요 오류 단위 수 감소 또는 중요 오류 단위 증가 없이 핵심 명제의 순증이다. 개선이 없으면 기존 등록을 유지한다. 복수 후보는 중요 오류 단위 수 → 핵심 명제 보존 수 → 핵심 질문 → 전체 질문 → 용어 → 자연스러움 → 총 입력 토큰 적은 순 → C1,C2,C3 순으로 한 번 선택한다. 실행 속도는 의미 기준을 앞서지 않는다.

개발 후보 선택은 등록 승인이 아니다. 최종 수용에는 [학습 준비 기준](../LEARNING_READINESS_BASELINE_20260911.md)의 전체 완결성, critical/major 각각0, 핵심 명제100%, 용어95% 이상, 질문95% 이상, 핵심 질문100% 및 기존 회귀 집합 조건이 모두 필요하다. 기존 소비한 test나 과거 실패를 새 결과로 덮어쓰지 않는다.

## 6. S3 관계 검사의 사전 범위

S3는 저장된 출력만 읽고 생성과 독립된 새 경고를 기록한다. 값+단위, 상대 %/%p, 시작값/증가분/결과값, 나눗셈 피제수/제수, 포함/제외와 부정 범위, after/during·only if 조건의 **양쪽 명시 인용이 있는 제한된 패턴**부터 지원한다. `supported_match`, `supported_conflict`, `undetermined`, `unsupported`, `source_ambiguous`를 구분한다. 사전 명제와 관계 패턴 이름을 정답 힌트로 넣지 않는다. 계산·의미 확정을 일반적으로 해결했다고 표시하지 않는다.

새 검사는 동결된 dev18·reading6의 기존 Hy7/Hy30 출력 전체를 먼저 진단 대상으로 한다(24원문×2=48출력). TG27의 실패16+성공2 및 일반16 비교의 기존 출력은 별도 회귀 층으로 연결한다. S3 manifest는 각 실제 존재 출력·원시 판정·해시·실행 상태를 검사 전에 명시하며 완료되지 않은 출력은 만들지 않는다. 이미 오류를 본 집합이므로 독립 탐지 성능이 아니다. 실제 오류만 골라 분모로 만들지 않는다.

각 지원 유형에 반대 의미의 정상 문장, 한국어 어순·동의 표현, 달러/기호·퍼센트포인트 표기, 부정 범위, 판단 불가·지원 밖을 포함한 반례를 검사 전에 별도 합성 진단으로 고정한다. 이 fixture는 모델 생성 출력과 섞지 않는다. 이번 S1은 그 범위 계약이며 S3의 실제 한국어 출력 fixture·검사 결과는 아직 없다.

TP/FP/FN/TN은 문단과 관계 유형별로 따로 계산하고 보류·미지원·실행실패·경고 범위를 함께 남긴다. 원래 숫자 통과/실패·번역 판정은 불변이다. 기존 원장에 새 검사 관측만 추가하고 동일 관측 재실행은 추가0이어야 한다. 이 제한된 검사 통과로 제품 QE95/95·빨간 구간 정확도·기지6개·하위집합 수용을 통과했다고 주장하지 않는다. 새로운 검사 등록용 독립 holdout은 별도 calibration/holdout 계약 없이는 시작하지 않는다.

## 7. 독립 평가 규모와 선정 절차

개발 결과를 보기 전 **금융60·일반20, 총80개의 새 단위** 계획을 고정한다. 기존 baseline의 fresh60 금융 최소치를 줄이지 않는다. 현재는 선정 절차만 동결하며 내용·명제·질문은 생성/열람하지 않았다. 후보와 selector/dictionary/runtime/prompt/평가 정책 해시를 동결한 뒤, 개발에 참여하지 않은 source curator가 새 문서 풀을 감사하고 내용과 주석을 별도 `.training/quality-evaluation/input-preparation-v1/holdout-v1/`에 작성한다. 개발자는 그 전에 이 경로를 입력 선택·사전 조정에 사용하지 않는다.

| 주된 층(중복 집계 없음) | 금융 | 일반 |
|---|---:|---:|
| 개념·문맥별 뜻 | 12 | 4 |
| 인과·비교 | 12 | 4 |
| 조건·부정·포함/제외 | 12 | 4 |
| 계산·수량·단위 | 12 | 4 |
| 여러 문장 연결·시점·지시 | 12 | 4 |

공개 영어 문서의 실제 구조를 사용한다. 금융 최소20문서·문서당 최대3단위, 일반 최소10문서·문서당 최대2단위로 정한다. 동일 저자·문서 군집도 보고하며 대표성을 보장하지 않는다. source 추출 상태와 self-contained 질문 가능성, 40~180 영어 단어의 대상, 허용 문맥, 명확한 source-only 명제를 요건으로 삼는다. 표·스캔·손상 원문은 이번 대상에서 제외하되 제외 수·사유를 보고한다.

원문 제목/URL/파일 해시/버전/인접 블록/정규화 본문·숫자 마스킹·근접중복으로 그룹을 묶어 기존 train/dev/test/평가·S1의 모든 문서 및 파생 버전을 배제한다. 이번 R01/R05와 합성 6쌍도 전체 그룹을 제외한다. 후보 번역을 보고 문서를 고르지 않는다. 적격 풀을 출처 URL+블록 위치로 정렬한 뒤 고정 salt `input-preparation-v1-holdout-20260913`의 SHA-256 순으로 층별 선정하고 전체 풀·제외·순서를 보존한다. 최소 문서 수나 고정 분량을 채우지 못하면 선정 미완료로 남긴다.

단위마다 원문 핵심 명제3·질문2(핵심1)를 번역 전에 감사·동결한다. 따라서 금융180명제/120질문(핵심60), 일반60명제/40질문(핵심20)이다. 용어는 선택한 원문의 문맥별 출현 inventory를 결과 관측 전에 확정하며 실제 분모는 아직 미정이다. 필요한 용어 주석이 없으면 통과로 표시하지 않는다. S1의39개를 holdout 분모로 복사하지 않는다.

선택 후보와 C0를 같은80단위에 한 번씩 적용하므로 **최대160출력**이다. 완성 출력의 임의 재생성·best-of 선택은 없다. 동결 이후 발견한 결함/실패/보류는 원분모와 함께 남기며 같은 holdout을 보며 재조정하지 않는다. 원문 문서별 군집과 출처 편향 때문에 80단위의 결과를 일반적95% 정확도 인증으로 확대하지 않는다. 질문 답변자는 개발과 같은 엄격한 미노출 조건을 따르며 못 구하면 그 평가만 미완료다.

## 8. 완료·중단과 다음 단계

S1 완료는 자료·명제·질문·사전·선정/중단 정책의 고정, source/평가의 인용·ID·해시 검증, 기존 test와의 유출 감사, 현재 등록 감사 및 별도 도우미 원문 대조로 판단한다. 동결 뒤 수정은 덮어쓰기 대신 새 정책/자료 버전과 이유를 남긴다. 단순 파일 생성이나 계획 링크만으로 S2/S3을 체크하지 않는다.

S2에서 실제 C0 prompt 재현과 네 구성의 token 예산/평가 비유출을 검증하지 못하면 생성은0이다. S4는 같은 입력의 고정 순서에서 단일 무거운 모델만 실행한다. 실행 직전 AC, physical/commit, 소유 프로세스·운영 worker 경합, CPU4·BelowNormal 및 해당 Hy7 프로필에 고정한 메모리 조건을 새로 확인한다. 현재 감사는 실행 preflight가 아니며 TG27 수치를 복사하지 않는다. 자원/소유 종료/기술 실패·잘림이면 실행 중지와 증거 보존, 자동 반복 없음이다. 자원 수치와 종료/대기 시간은 S4 producer manifest에서 최초 번역 전에 고정해야 한다.

품질이 나쁜 완성 출력은 그대로 보존하고 좋은 출력으로 교체하지 않는다. 기술 실패를 고쳐 이어야 한다면 새 코드/run 정체성, 원래 실패/미완료 및 기존 완료의 재사용 이유를 별도 기록한다. 기준을 완화하거나 분모를 줄여 통과시키지 않는다. S1은 모델 설치·생성·번역 품질 개선·앱 테스트·앱 반영 완료를 주장하지 않는다. 다음 승인된 작업 단위는 S2 입력 준비 구현과 S3 저장 출력 진단이며, 이번 사용자 요청 범위는 S1까지다.
