[계약](CONTRACT.md)은 C0의 실제 대상 중복·UTF-16 자르기, C1~C3 문맥/사전 차이, 실제 tokenizer의4095 입력토큰 한도, 인용 출처와 지원 밖 처리, 정답 비유출, 단위×후보별 한국어 답변 격리, 후보 선택·회귀 거부·중단·독립80 선정 절차를 정한다. [manifest](freeze-manifest.json)는 파일 바이트와 단위·버전·출처·고정 분모를 연결한다. 일반 사전은 [JSON](sense-dictionary.json)과 [출처 설명](DICTIONARY_SOURCES.md)에 있고, 평가 정답은 별도 `evaluation/` 및 로컬 전용 평가 파일에 있다.

현재 Hy7의 [입력 감사](CURRENT_INPUT_AUDIT.md)에서 모델 전체7,981,928,896바이트와 등록·runtime·code 등104파일을 검증했다. 등록54 사전에는 단독 equity가 없고, bridge는 앱에서 받은 일반 glossary 대신 등록 사전을 사용한다. 현 공통 지시가 금융 뜻의 참조만 허용하므로 C2/C3의 비금융 뜻은 힌트로 직접 넣지 않도록 계약을 맞췄다. 이 감사는 실제 tokenizer/번역 프로세스의 시작이나 현재 RAM/전원 검사와 다르다.

선정 공개 원문4개는 기존 Marian train과 중복하므로 알려진 회귀 자료로 표시했다. 자료의 새 조합을 새 독립 자료로 해석하지 않는다. source-only 중복 감사는 기존14파일의2,345개 원문/문맥 행과 대상·유지 문맥을 비교했다. 기존 소비 test와의 완전·숫자 마스킹·포함·근접 중복은0개, 새 집합의 그룹 밖 대상 중복은0개였다. 검사 과정에서 test source 필드를 기계적으로 읽었지만 답변·원문 내용은 도우미에게 출력하거나 새 파일로 편입하지 않았다. 의미상 모든 유사성을 검출했다는 뜻은 아니며 독립 평가는 기존 문서 그룹 전체를 배제한다.

별도 도우미가 금융8의 원문·명제·질문·용어를 대조했고 root가 일반8을 대조했다. 동결 전에 F03 부정의 전체 인용, F04 입력별 오류 가능성의 범위, F07/08 예산의 가정 표현을 보강했다. F06은 상대2%를 `of its starting level`로 명시해 %p 혼용 가능성을 줄였다. 계약 검토에서 힌트의 prompt/sidecar 필드와 최소대립쌍 간 답변 노출도 수정했다. 모두 **도우미 검토**이며 사람 gold·사용자 검수·번역 평가가 아니다. 구체적인 수정과 검토 범위는 [검토 기록](author-review.json)에 남겼다.

Windows PowerShell에서 다음 명령으로 고정 자료와 현재 로컬 의존 파일을 읽기 전용으로 재검증한다. Python 표준 라이브러리만 사용하고 앱/학습 모듈·SQLite·모델을 import하지 않는다. 새 보고서를 남길 때만 사용하지 않은 `--output .training/verifications/<새이름>.json`을 추가한다.

```powershell
.venv-training\Scripts\python.exe -B -X utf8 scripts/model-comparison/verify_input_preparation_v1.py
```

재검증에는 Git에서 제외된 공개 source 묶음2파일, 기존 데이터14파일, 감사한 로컬 설치104파일이 필요하다. 공개 source 묶음과 로컬 검증 기록은 `.training/comparisons/input-preparation-v1/source-bundles/`와 `.training/verifications/`에 별도 보관해야 한다. 이 비교 산출물은 SQLite 백업에 포함되지 않는다. 누락 시 해시 검증은 실패하며 운영 DB에서 몰래 재생성하지 않는다.

이번 검증은 JSON·묶음 내부 소속·인용/용어 위치·분모·중복·해시·문서 링크 검증이다. 공개4단위의17블록 참조는 별도 읽기 전용 DB 대조로 실제 소속·본문·구조를 확인하고 그 receipt도 동결했다. 필수 artifact 누락/중복, 버전→자료·블록→버전의 전역 불일치와 UTF-8 손상을 검증기가 거부한다. 새 자료·검증기는 `.gitattributes`의 한정된 LF 규칙으로 Windows checkout의 바이트 변화를 방지한다. 앱 build/E2E, 실제 엔진 HTML3문단·PDF1페이지 생성/저장/캐시, tokenizer token 수 검증은 실행하지 않았다. 운영 DB·개인 기록·기존 원문 버전·활성 등록·과거 원장과 고정 출력은 변경하지 않았다. 다음 단계는 이 계약으로 S2를 구현하고, 실제 prompt와 token 수를 고정하는 것이다.
