# 금융 학습용 번역 하방과 로컬 실행 최적화

2026-09-10 사용자의 무료 로컬 모델 실행 승인에 따른 새 개발 비교다. 기존 v5 최종 시험과 Q26은 이미 소비된 평가 자료이며, 이번 독립 최종 시험이나 학습 자료로 재사용하지 않는다. 이 문서는 새 모델 출력을 보기 전에 작성한 실행 원칙이다.

## 선택 순서

1. 실제 메모리와 공개 모델의 출처·파일 무결성·번역 템플릿을 확인한다.
2. 현재 앱의 Hy-MT2 7B Q8 문맥 구성을 새 개발 자료의 기준으로 사용한다.
3. TranslateGemma 27B Q4와 Hy-MT2 30B-A3B Q4는 파일만 각각 약 15.41GiB와 16.98GiB다. 이 PC의 전체 RAM은 31.51GiB이며, 앱의 대기 작업이 없음을 확인하고 기존 번역 엔진을 중지한 직후의 초기 여유 RAM은 약 9.93GiB였다. 사용자 소유의 다른 앱을 종료하지 않는다. 일반 실행은 가중치 전체 상주에 실행 버퍼·KV 캐시·운영체제 여유를 더한 보수적 예산을 사용하며, 맞지 않으면 보류한다. 아래의 추가 제한 실험과 구분하고, mmap이나 MoE의 활성 파라미터 수만으로 실제 메모리 절감량을 주장하지 않는다.
4. 실제 자원에 맞는 TranslateGemma 12B Q4를 우선 대안으로 확인한다. 같은 기반 모델의 12B와 27B는 별도 후보이며 결과를 서로 대신하지 않는다. 12B도 설치·메모리 검사와 실제 실행을 통과해야 한다.
5. Intel GPU/SYCL과 CPU 설정은 별도 짧은 기능·성능 입력에서 확인한다. GPU는 공유 RAM을 쓰므로 추가 전용 메모리가 있다고 가정하지 않는다. 실패·중단도 보존하고 검증되지 않은 속도 개선을 주장하지 않는다.

사용자가 번역 결과의 품질이 처리 시간보다 우선임을 다시 명시했고, 다른 프로그램을 직접 닫아 메모리를 확보하겠다고 답했다. 이에 27B·30B 다운로드를 재개하고 실제 여유 메모리를 다시 확인해 품질 비교에 포함한다. 느리다는 이유만으로 큰 후보를 제외하지 않는다. 추가 속도 튜닝은 중단하며, GPU 기능 시험의 가속은 번역 품질 개선으로 세지 않는다.

## RAM을 제한하는 추가 실험

전체 가중치 상주는 읽기 전용 파일 매핑의 정확성 필수조건이 아니라 과도한 페이지 교체를 피하는 보수적 실행 조건이다. Windows는 비상주 부분을 원본 파일에서 읽을 수 있다. 이를 실제 메모리 절감이나 완료 보장으로 가정하지 않고, 속도 저하를 허용하는 별도 제한 실험으로만 확인한다. 원래 Q4 가중치·번역 템플릿·샘플링은 유지한다. [Microsoft 파일 매핑 설명](https://learn.microsoft.com/en-us/windows/win32/memory/creating-a-file-mapping-object)

작은 원문 없는 실험에서 Job의 작업 집합 설정은 Windows 오류 1314로 실패했다. 개별 프로세스의 API 적용과 재조회는 성공했으나 요청 128MiB보다 실측 최대가 4KiB 높아 최초의 엄격한 검사는 실패로 보존했다. 후속 실험은 관측 예산 128MiB를 유지하고 API 요청을 127MiB로 낮추는 정책을 실행 전에 고정했다. 이때 최대 127MiB+4KiB, 파일 256MiB의 반복 읽기 내용 일치와 종료를 확인했다. 첫 실패를 통과로 바꾸거나 번역 품질 기준을 완화한 결과가 아니다. 원시 증거는 `.training/comparisons/working-set-helper-verification-20260910.json`에 있다.

제한 실험은 프로세스의 관측 작업 집합 예산을 실행 전에 명시하고, API 요청은 선택 예산보다 64MiB 낮춘다. 시작 전에는 선택 예산에 3GiB를 더한 가용 물리 메모리와 별도 commit 예산을 요구한다. 처음 준비한 11·12GiB와 이후 10GiB 설정은 실제 대형 모델 실행 전에 보존했다. 다른 프로그램의 사용량 변화로 모델이 없는 상태의 여유 RAM이 약 11.8GiB까지 줄어, 최저 8GiB부터 12GiB까지 명시적으로 선택하는 준비로 이어갔다. 첫 27B 기능 시험은 시작 직전 자원을 다시 확인한 뒤 8GiB 예산과 최소 11GiB의 물리 여유를 요구한다. 그보다 낮게 계속 축소하지 않는다.

27B의 GGUF 헤더상 최대 단일 tensor는 약 1.077GiB, 최대 layer의 tensor 합은 약 0.247GiB다. 기존 KV·private 여유 추정 약 3.969GiB와 비교하면 8GiB 작업 집합이 구조적으로 즉시 불가능하다는 근거는 없지만, 이는 실제 작업 집합이나 완료를 보장하는 계산이 아니다. 이 선택은 모델의 상주량을 줄일 뿐 양자화 정밀도·문맥·번역 설정·의미 평가 기준을 낮추지 않는다. 주 스레드를 중지 상태로 생성해 소유 Job 배정·한도 적용·재조회 후 재개하는 경로는 작은 프로세스로 검증했다. 다음으로 실제 모델 시작과 짧은 기능 번역을 확인한 뒤 전체 개발 비교 여부를 결정한다. 이전 일반 실행기를 수정하지 않고 별도 버전·출력·코드 해시를 남긴다. 많은 페이지 교체로 실행이 시간 제한을 넘거나 자원 감시로 중단될 수 있으며, 이를 품질 실패나 정상 번역 완료로 바꾸지 않는다.

작업 집합은 프로세스의 상주 페이지를 뜻하며 OS 파일 캐시나 전체 commit의 상한이 아니다. 파일 선읽기도 프로세스 작업 집합 바깥의 물리 메모리를 사용할 수 있다. 따라서 실제 물리·commit 여유, 프로세스 작업 집합·private 메모리·페이지 부재 횟수, 지연, 실패와 종료를 함께 기록한다. 자원 감시와 시간 제한이 시스템 정체나 메모리 부족을 완전히 막는다고 보증하지 않는다. [작업 집합 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-setprocessworkingsetsizeex), [파일 선읽기 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-prefetchvirtualmemory)

## 언어학적 기준

문장이 자연스럽더라도 학습자가 다른 명제를 이해하게 되면 의미 오류다. 주체와 지급·수취 관계, 부정의 범위, 필요조건과 충분조건, 가능성과 의무, 수치와 단위의 관계, 문맥에 맞는 다의어, 금융 개념의 구체성, 문장 간 지시 관계를 별도로 대조한다. 최소대립쌍의 한쪽만 맞으면 그 구별을 성공한 것으로 세지 않는다.

새 자료는 `development_screen`으로 명시하고 원문·문맥·참조 번역·진리조건·용어 기준을 분리한다. 도우미가 작성하고 다른 도우미가 대조해도 사람 검수본이 아니다. 모델에는 허용 목록으로 뽑은 원문과 해당 모델이 지원하는 문맥만 전달한다. 참조 번역·정답 용어·오류 체크는 추론 입력에서 제외한다. TranslateGemma는 원래 번역 템플릿에 원문을 넣고, Hy-MT2는 기존 조건부 용어집과 문맥 구성을 사용하므로 순수 가중치 효과가 아닌 실제 사용 구성의 비교다.

판정은 치명적 관계·조건 반전, 그 밖의 중요한 의미 오류, 경미한 표현·정밀도 문제, 한국어 자연스러움을 구분한다. 용어 표기와 올바른 뜻을 함께 확인하며, 숫자 문자열이 같다는 이유로 수량 관계까지 보존됐다고 판단하지 않는다. 자동 숫자 검사 경고와 의미 오류의 개수도 별도로 보고한다.

## 실행과 결정

비교 출력은 `.training/comparisons/`의 새 디렉터리에 저장하고 기존 결과를 덮어쓰지 않는다. 모델·런타임·코드·입력·생성 설정·실제 종료 토큰과 처리 시간을 기록한다. 실행 중 한 번에 무거운 모델 하나만 올린다. 분량 제한·잘림·실패·중단을 성공 번역에 포함하지 않는다.

사용자의 추가 지시에 따라 각 실행이 끝나거나 실패하면 해당 실행이 소유한 모델과 임시 프로세스를 종료하고, 종료 확인 및 실제 가용 메모리를 기록한다. 가중치 파일·학습 결과·평가 기록을 지워 RAM을 확보하는 방식은 사용하지 않는다. 다른 앱의 메모리 확보는 사용자가 직접 수행하며, 확보하겠다는 답변과 실제 확보된 메모리를 구분한다. 다음 모델을 시작하기 직전에 물리 메모리와 Windows의 남은 commit 한도를 다시 확인한다.

개발 비교만으로 최고 품질이나 금융 용어 90% 이상을 인증하지 않는다. 개선 후보가 관측되면 별도 독립 자료에서 확인하고, 앱용 변환·실제 추론 검증을 거쳐 선택한다. 큰 모델이 메모리에 맞지 않거나 새 후보가 의미 품질을 개선하지 못하면 현재 등록을 유지한다. 현재 학습된 Marian의 가중치나 소비된 test를 다시 조정하지 않는다. 새 가중치 학습은 적절한 기반 모델과 남은 오류가 확인된 뒤 별도 실험으로 설계한다.
