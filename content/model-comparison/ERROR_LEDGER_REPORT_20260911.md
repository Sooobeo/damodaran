### 기존 검사 코드에서 확인한 범위

숫자 검사 함수 `run_hymt.numeric_tokens`의 고정 코드만 추출해005/006의 실제 원문·번역에 재적용했다. 네 텍스트 모두 `4%:1, 2%:1`로 읽혔다. 숫자 뒤의 `percent`를 `%`로 정규화하고 `point`나 `%p`의 `p`는 토큰에 포함하지 않는 구현 때문에 단위 대립을 판별하지 못한다. `numbersPreserved:true`가 재현됐으며 원래 판정은 그대로다. 근거는 `.training/verifications/tg27-numeric-check-reproduction-20260912.json`이다. 이것은 자동 검사가 놓친 이유이며 모델이 오역을 생성한 내부 원인을 설명한 것은 아니다.

별도 기존 앱 의미 규칙 `finance-meaning-rules-v1`도 코드 변경 없이 실제16문단에 적용했다. 중요 오류5문단 중006의 상대2%→2%p 한 문단만 경고했다. 확정 비중요6문단은 경고0, 중요4문단은 미탐이며 보류5문단은 정답/오답 분모에서 제외하고 관측 상태를 남겼다. 수치는 TP1·FP0·FN4·TN6·판정 보류5, 확정 중요 오류 재현1/5=20%다. 단일 경고의 정밀도를 전반적인95% 수용으로 확대하지 않는다. 기존 `financing-equity-sense`의 제한된 어순 패턴은008의 `equity in ... financing mix`에 맞지 않으며 시점·증분 관계를 대조하는 규칙은 없다. 규칙 확장·원문/번역 변경·모델 호출·앱 등록은 하지 않았다.

`.training/verifications/tg2716-existing-meaning-rules-20260912.json`에 실제 경고와 UTF-16 구간 검증을 보존했다.006의 원문 증가 문장과 한국어 `2%p`에 해당하며, 구간 유효성을 다른 오류의 탐지 성능으로 표시하지 않는다. 이16개 검사 관측을 기존 번역 사건과 해시로 연결해724사건이 됐고 반복 추가0·재사용16이었다. 보류는 `observed_unadjudicated`, materialError=null로 유지한다. 최신 보고서는 `.training/quality-evaluation/error-ledger/v1/reports/20260912T025458365421Z.json`이다.
