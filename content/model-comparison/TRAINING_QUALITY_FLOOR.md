# 학습용 금융 영한 번역의 최소 수용 기준

작성일: 2026-09-10. 무료 로컬 번역 모델이 만든 문장을 다음 모델의 학습 자료로 채택할 때 적용할 정책이다. **원문에 충실하다는 근거가 없는 번역은 양을 채우기 위해 학습에 넣지 않는다.** 새 번역 생성 모델의 원문 대조와 실제 자료 비교를 마치기 전에는 대량 번역·추가 가중치 학습을 보류한다. 소규모 후보 생성·검토와 학습 자료 확정은 구분한다.

이 문서는 수용 기준을 정리한다. 새 데이터 생성, 학습 실행, DB 상태·운영 번역·제공자 변경을 수행하거나 자동 검수 기능을 구현한 문서가 아니다. 기준을 만족한 표본이 있더라도 전체 번역의 최저 품질이나 용어 적중 90%를 보장하지 않는다.

## 1. 용어 점수만으로 학습 자료를 채택하지 않는 이유

[v5 결과](../training/FINANCE_V5_REPORT.md)는 고정 최종 시험에서 기준 용어 **103/110, 93.64%**를 맞혀 당시 사전 통과 기준을 충족했다. 그러나 별도의 익명 도우미 대조에서는 **140행 중 50행에 실질적인 의미 오류**가 남아 앱 기본 모델로 선택하지 않았다. 이 두 수치는 다른 것을 측정한다. 용어 표기가 맞는 문장도 지급 방향, 부정의 범위, 수량 관계를 틀릴 수 있다. 기존 v5 판정을 소급해서 실패로 바꾸는 대신, 후속 학습 자료에는 문장 전체의 의미 보존을 별도로 요구한다.

현재 [언어학적 개발 자료](linguistic-dev-20260910.jsonl)의 익명 두 후보도 `LDEV26-008`에서 같은 핵심 문제를 보였다. 자금 조달 구성의 `equity`를 각각 **균형**, **공평성**으로 옮겨 자기자본의 뜻을 놓쳤다. 이 관측은 [독립 도우미 감사](../../.training/verifications/linguistic-packet2-independent-audit-20260910.json)에 기록되어 있다. 두 모델의 답이 비슷하거나 검토 모델이 자연스럽다고 평가한다는 사실만으로 정확성을 인정할 수 없다. 이 감사는 사람 검수나 독립 최종 품질 인증이 아니다.

## 2. 번역 전에 원문의 명제를 확정한다

학습 후보의 단위는 문장 또는 문맥이 충분한 문단이다. 검토자는 번역의 문구를 따라 정답 기준을 만들지 않고, 먼저 원문과 필요한 이웃 문맥에서 다음 항목을 적는다. 모든 항목을 기계적으로 채우는 대신 해당 문장에 있는 관계를 빠짐없이 확인한다.

| 확인 대상 | 원문에서 확정할 내용 | 번역의 수용 기준 |
|---|---|---|
| 행위자·대상·수취인 | 누가 누구에게 무엇을 지급·보고·보유하는가 | 지급자와 수취인, 채권자와 채무자, 보고자와 대상의 방향을 보존한다. 수동태·한국어 어순 변경은 허용한다. |
| 조건·부정·수량 범위 | 어떤 집합에 어느 조건과 부정이 적용되는가 | 필요조건을 충분조건으로 바꾸지 않는다. 전부가 아님과 아무도 아님을 구분하고, 원문에 없는 지급자 존재를 추가하지 않는다. |
| 의무·허용·가능성·예측 | 해야 함, 해도 됨, 가능함, 예상함 중 무엇인가 | 의무를 완료 사실로, 가능성을 확정 결과로 바꾸지 않는다. 더 강한 예측도 원문에 없는 절대 보장으로 강화하지 않는다. |
| 수량·단위·수식 관계 | 수치의 대상, 시작 값·증가분, 기준 비율, 기간, 연산자의 적용 범위 | 같은 숫자가 있어도 다른 대상에 붙거나 상대 증가가 퍼센트포인트 증가로 바뀌면 보류한다. 개수와 개별 대상의 정체도 구분한다. |
| 다의어·금융 용어 | 이 출현에서 어느 뜻이며 무엇을 가리키는가 | 금융 기관이 등장한다는 이유만으로 단어의 금융 의미를 강제하지 않는다. 뜻이 맞는지와 기준 표기를 썼는지는 각각 판정한다. |
| 담화·참조·시간 | 대명사·전자/후자·이 추정치의 지시 대상, 발언의 주체, 사건의 선후 | 위원회의 예측을 관측 사실로 바꾸거나 통합 이후를 통합 과정 중으로 옮기지 않는다. 한국어에서 생략한 주어도 일관되게 복원되어야 한다. |
| 누락·추가·한국어 | 남아야 할 한정과 관계, 원문이 말하지 않은 내용 | 핵심 명제와 필요한 한정을 보존한다. 자연스러운 문장 결합·분리·표현 차이는 허용하되 새로운 결론·원인·권리·계산값을 본문에 넣지 않는다. |

원문이 특정하지 않은 사항은 특정하지 않은 상태로 보존한다. 문서의 종류나 권리의 대상을 추측해 그럴듯하게 채우는 번역은 적격으로 만들지 않는다. 원문이 복수 해석을 허용할 때 번역도 그 범위를 유지할 수 있다. 검토자가 하나의 해석을 확정하지 못했다는 이유로 임의의 해석을 정답으로 고정하지 않는다.

원문 자체에 문자 손상, 잘린 문장, 빠진 수식, 읽기 순서 오류, 해결되지 않은 표·그림 참조가 있으면 먼저 원문 단계에서 보류한다. 이미 저장한 원문과 블록을 학습용 수정본으로 덮어쓰지 않으며, 재추출이 필요하면 원문 버전 관계를 보존한다. [R05 문자 해독 조사](R05_SOURCE_DECODING_NOTE.md)가 이런 분리의 예다.

## 3. 한 문장쌍을 수용하는 조건

다음 조건을 **모두** 충족한 문장쌍만 학습 자료의 수용 후보로 둔다. 이는 해당 검토에서 관측한 오류가 없다는 뜻이며 사람 검수 완료를 의미하지 않는다.

1. 원문·문맥·출처·문서/버전/블록 또는 작성 예시 ID가 확인되고, 원문 상태가 번역 가능하다.
2. 원문에서 추출한 명제와 번역을 대조했으며 행위자·조건·부정·모달 강도·수량·다의어·참조의 미해결 오류가 없다.
3. 알려진 경미한 오역·필수 한정 누락·부자연스러운 한국어도 수정 후 다시 대조했다. 단순 종결 문체, 자연스러운 동의 표현, 공백 차이를 오류로 만들어 고치지는 않는다.
4. 숫자·부호·통화·단위·수식·누락·잘림·제어 문자열의 자동 검사 결과를 확인했다. 검사 경고를 없애기 위해 원문에 없는 숫자를 넣거나 정답 기준을 바꾸지 않았다.
5. 생성자와 구분된 검토 기록에 원문·번역의 실제 근거 구절, 수정 내용, 남은 의문과 최종 처리 이유가 있다. 판단이 갈린 항목은 해결 전까지 보류한다.
6. 분할·중복·소비 이력 검사를 통과하고, train에 사용할 수 있는 출처 및 용도로 확정되어 있다.

상태는 다음처럼 운용한다. 아래 상태는 정책상 구분이며 새 DB 필드가 구현되었다는 뜻이 아니다.

| 상태 | 처리 |
|---|---|
| 수용 후보 | 모든 조건과 근거를 확인했다. train의 manifest·해시·출처를 확정한 뒤에만 가중치 갱신 대상으로 삼는다. |
| 보류 | 의미 오류, 검토 불일치, 부족한 문맥, 원문 손상 또는 해결되지 않은 경고가 있다. 번역과 검토 이력은 보존하고 train에서는 제외한다. |
| 제외 | 기존 dev/test·소비한 진단 예시, 분할 누수, 부적절한 이용 조건 등으로 해당 학습에 사용할 수 없다. 표현을 조금 바꿔 다시 넣지 않는다. |

보류 항목은 번역을 수정했다고 곧바로 통과시키지 않는다. 수정 전후의 전체 문장을 원문에 다시 대조하고, 앞서 지적한 오류의 해결과 새로운 누락·추가가 없는지 확인한다. 검토자가 결론을 내리지 못하면 다수결이나 모델의 높은 자신감으로 통과시키지 않는다.

## 4. 생성 모델과 검토의 독립성을 구분한다

생성 모델의 자기평가, 같은 모델의 재생성, 역번역은 오류를 찾는 보조 수단이다. 동일한 다의어 해석이나 잘못된 전제를 반복할 수 있으므로 이것만으로 수용 조건을 충족하지 않는다. 서로 다른 모델도 학습 자료·언어 관습·용어 편향을 공유할 수 있으며, 두 후보가 모두 틀린 `equity` 사례가 실제로 관측되었다.

가능한 경우 검토자는 모델 이름·속도·용어 점수를 보기 전에 원문을 읽고 판단한다. 생성자의 답을 본 다른 모델이 동의한 경우와, 원문에서 먼저 명제를 정리한 별도 검토는 독립성의 정도가 다르다. 사람이 참여하지 않았으면 어떤 방식이든 사람 검수본으로 표시하지 않는다. 이미 본 문장을 다른 후보와 재비교할 때에는 검토자가 문장을 기억할 수 있다는 한계도 남긴다.

용어 표기는 원문 출현의 뜻을 확인한 뒤 평가한다. 정규 표기가 문장 어딘가에 있다는 이유로 다른 출현의 오용을 정답으로 세지 않는다. 숫자 다중집합 일치, 문자 유사도, BLEU·chrF, 모델의 품질 점수도 단독 수용 조건이 아니다. 날짜의 자연스러운 한국어 표기 같은 변환은 실제 의미를 대조하여 설명하고 자동 검사 기록을 지우지 않는다.

## 5. 본문 번역과 학습 해설을 분리한다

학습의 target에는 원문에 대응하는 번역만 넣는다. 번역을 이해하기 위해 작성한 명제 목록, 용어 뜻의 해설, 계산 과정, 오류 설명, 추정 근거는 별도 검토 기록에 둔다. 원문이 결과값을 주지 않았다면 친절한 계산값을 번역 본문에 덧붙이지 않는다. `may`를 옮긴 뒤 확정적 전망을 해설로 붙이는 식의 보완도 금지한다.

아래는 이미 공개된 개발 자료에서 가져온 **검토 기준 설명용 예시 세 개**다. 한국어 열은 완성 번역이 아닌 의미 개요다. 예시 원문·참조·개요·숫자만 바꾼 변형을 새 train에 넣지 않는다.

| 개발 ID와 영어 원문 | 반드시 남아야 할 의미 개요 |
|---|---|
| **LDEV26-001** — “Under a draft shipping agreement, the carrier must reimburse the exporter for $1,800 of inspection fees. The customs office receives none of that reimbursement.” | 운송업체가 비용 보전 의무자이고 수출업체가 수취인이다. 대상은 검사 비용 1,800달러다. 계약 초안에 따른 의무이며 이미 지급한 사실은 아니다. 세관은 보전금을 받지 않는다. |
| **LDEV26-006** — “In a training spreadsheet, the expense ratio starts at 4%. The analyst increases it by 2% before running the comparison; the starting value is not itself the increase.” | 4%는 시작 비율, 2%는 시작 값에 대한 상대 증가다. 비율에 2퍼센트포인트를 더하는 말로 바꾸지 않는다. 비교 전 조정이라는 순서를 보존한다. 기존 값 대비라는 문구를 반드시 쓰거나 계산 결과를 본문에 추가할 필요는 없다. |
| **LDEV26-008** — “The reviewer called for greater equity in the fund's financing mix, not a fairer hiring policy. Her comment concerns how the fund is financed.” | 자금 조달 구성에서 자기자본을 늘리라는 요구다. 자기자본의 금액 또는 비중을 늘린다는 자연스러운 해석을 허용하되 공평성이나 균형으로 바꾸지 않는다. 채용 공정성 개선을 요구한 발언은 아니다. |

## 6. 출처와 평가 분할을 보존한다

사용자가 검수한 번역, 도우미가 작성한 예문쌍, 공개 원문을 로컬 모델로 번역한 쌍을 구분한다. 각 쌍에는 원문 출처·버전·해시, 생성 모델의 revision·실제 가중치/런타임·프롬프트/설정 해시, 원시 출력, 수정 전후 번역, 검토자 유형·근거·시각, 분할과 사용 가능 여부를 남긴다. 도우미가 다시 대조하거나 수정했어도 `humanReviewed=false`는 유지한다. 공개 자료의 한국어 공식 번역인 것처럼 표시하지 않는다.

실제 문서는 원문 문서 단위로 train/dev/test를 먼저 나눈다. 같은 문서의 인접 문단·다른 추출 버전·반복 표제를 다른 분할에 섞지 않는다. 독자 작성 문장도 동일 명제, 숫자만 바꾼 문장, 근접한 바꿔 쓰기를 검사한다. 분할을 정한 뒤 평가 결과를 보고 어려운 문장을 train으로 옮기거나 평가 분모에서 제거하지 않는다.

소비한 dev/test·최종 시험·개발 진단은 다시 학습하지 않는다. 이번 18개 개발 문장, 실제 원문 6개 비교 자료, 앞선 v5 최종 시험과 이 문서의 예시도 대상에 포함된다. dev는 정해 둔 선택 절차 안에서만 사용하고, 최종 test는 선택을 끝내고 모델·설정·데이터·평가 방법을 고정한 뒤에 사용한다. 실패한 최종 시험을 보고 같은 시험을 통과하도록 재학습하지 않는다.

## 7. 대량 번역·학습을 다시 시작할 조건

먼저 후보 모델의 실제 완료 출력에 대해 원문 중심 의미 검토와 실제 읽기 자료 비교를 끝낸다. 모델 크기, 설치 완료, 시작 검사 통과, 생성 개수 또는 처리 속도만으로 학습 자료 생성 모델을 선정하지 않는다. 다의어·조건·수량·담화의 반복 오류를 확인하고, 해결되지 않은 후보 출력을 대량 생산하지 않는다.

그 뒤 train 전용 원문에서 소규모 번역 후보를 만들고 이 문서의 행별 기준을 적용한다. 어떤 오류로 몇 개를 보류했는지, 검토가 어느 출처·영역을 다뤘는지와 미해결 항목을 기록한다. 수용 후보의 해시·출처·분할과 검토 범위를 확정하기 전에는 본학습을 시작하지 않는다. 수용률이나 목표 문장 수를 맞추려고 보류 기준을 낮추지 않는다.

새 가중치를 학습했다면 가중치 변화, dev 선택, 독립 test, 앱용 추론과 실제 저장·캐시 검증은 여전히 별도 단계다. 학습 도구의 실행 경계는 [SYSTEM_DESIGN.md 8.4절](../../SYSTEM_DESIGN.md#84-실제-모델-학습의-실행-경계)과 [학습 도구 안내](../../scripts/model-training/README.md), 의미 검토 형식은 [언어학적 검토 계약](../../scripts/model-comparison/LINGUISTIC_REVIEW.md)을 따른다.
